# しおりアプリ コンポーネント一覧

## 概要

バックエンド（Java / Spring）未実装のため、**Next.js の UI コンポーネントのみ**を先に実装する。  
データはモックで差し込み、API 接続は後から行う。細かいデザインは後続で調整する。

| 項目 | 方針 |
|------|------|
| フロント | Next.js（App Router 想定） |
| この段階の範囲 | 画面・コンポーネントの見た目と操作フロー |
| この段階でやらない | API 実装、認証の本番接続、デザインの細部調整 |

関連: [要件定義.md](./要件定義.md) / [API設計.md](./API設計.md) / [デザイン方針.md](./デザイン方針.md)

**デザインの方向性**: 淡いベージュのノート帳。横罫線を背景・入力エリアに取り入れる（詳細は [デザイン方針.md](./デザイン方針.md)）。

## 画面（ページ）とルート案

| # | 画面 | ルート案 | 主な操作 |
|---|------|----------|----------|
| 1 | アカウント新規登録 | `/signup` | 登録フォーム送信 |
| 2 | ログイン | `/login` | ログイン |
| 3 | しおり一覧 | `/itineraries` | カード一覧・退出・作成へ |
| 4 | しおり作成 | `/itineraries/new` | 新規登録 |
| 5 | しおり内容 | `/itineraries/[id]` | 日ごと編集・コメント・写真へ |

| 7 | しおり管理 | `/itineraries/[id]/admin` | メンバー・設定・削除 |
| 8 | 招待受領 | `/invitations/[code]` | 参加確定 |

## 実装の優先順（UI のみ）

1. **共通部品** — ボタン、入力、モーダルなど、全画面で使うもの
2. **認証まわり** — ログイン / 新規登録（入口が単純）
3. **しおり一覧 + 作成** — アプリのホーム
4. **しおり内容（日ごとページ）** — 本体。コメント付き
5. **写真一覧 + 詳細**
6. **しおり管理 / 招待 / 設定**

## 1. 共通 UI（プリミティブ）

見た目は [デザイン方針.md](./デザイン方針.md) のノート帳テーマに沿う。まずは **役割がはっきりした部品** として切り出す。

| コンポーネント | 役割 | 使う画面 |
|----------------|------|----------|
| `Button` | 主操作・副操作・危険操作（削除・BAN） | 全体 |
| `TextField` | 1行入力（ユーザー名、メール、パスワード、タイトル） | 全体 |
| `TextArea` | 複数行（補足、備考、お約束、コメント） | 作成・内容・管理 |
| `PasswordField` | パスワード入力（表示切替は後でも可） | 認証・作成・管理・招待・設定 |
| `DateRangeField` | 期間（開始日〜終了日） | 作成・管理 |
| `Toggle` | 編集権限 ON/OFF、コメント解放 | しおり内容（管理者） |
| `Modal` | 確認（退出・削除・ログアウト・BAN） | 一覧・管理・設定 |
| `AppHeader` | 戻る、画面タイトル、設定への導線 | ログイン後 |
| `EmptyState` | しおりゼロ、写真ゼロなど | 一覧・写真 |
| `ErrorText` | バリデーション表示（英数字10文字以上など） | フォーム全般 |

## 2. 画面ごとのコンポーネント

ページ本体（`page.tsx`）はレイアウトと組み立てに留め、**塊はコンポーネントに切り出す**。

### 2.1 新規登録 `/signup`

| コンポーネント | 役割 |
|----------------|------|
| `SignupForm` | ユーザー名・メール・パスワード |

### 2.2 ログイン `/login`

| コンポーネント | 役割 |
|----------------|------|
| `LoginForm` | メールまたはユーザー名＋パスワード |

### 2.3 しおり一覧 `/itineraries`

| コンポーネント | 役割 |
|----------------|------|
| `ItineraryList` | 作成順のカード列 |
| `ItineraryCard` | タイトル・補足・期間。クリックで内容へ |
| `LeaveItineraryButton` | 退出。確認モーダルを開く |
| `CreateItineraryButton` | 「しおり作成＋」→ 作成画面へ |

### 2.4 しおり作成 `/itineraries/new`

| コンポーネント | 役割 |
|----------------|------|
| `CreateItineraryForm` | タイトル（必須）・パスワード（必須）・補足・期間 |

### 2.5 しおり内容 `/itineraries/[id]`

日ごとページが中心。コメントは各記述要素の横に付ける。

| コンポーネント | 役割 |
|----------------|------|
| `ItineraryHeader` | しおりタイトル・補足・期間・戻る |
| `OwnerControls` | 編集権限トグル、コメント解放トグル、管理画面へ（作成者のみ表示） |
| `PromisesSection` | お約束の表示 / 編集 |
| `DayTabs` または `DayPager` | ◯日目の切り替え |
| `DayPage` | 1日分のまとまり |
| `DayTitleField` | その日のタイトル |
| `RoadmapList` | カレンダー形式の予定一覧 |
| `RoadmapItem` | 時刻・内容・金額の1件 |
| `RoadmapItemForm` | 予定の追加 / 編集 |
| `DayNotesField` | 備考 |
| `DayCostField` | 概算 |
| `RepresentativePhoto` | その日の代表写真（管理者は一覧から1枚選択） |
| `CommentTrigger` | 要素横の「＋」 |
| `CommentThread` | その要素のコメント表示 |
| `CommentForm` | 投稿・編集 |
| `PhotoAlbumLink` | 写真一覧への遷移 |

コメント対象（`target_type` + `target_id` + `target_field`）は UI では「どの要素の横か」として持つ。API 接続時にそのまま渡す。

### 2.6 写真一覧 `/itineraries/[id]/photos`

| コンポーネント | 役割 |
|----------------|------|
| `PhotoToolbar` | 並び替え（日付 / いいね）、絞り込み（日付・ユーザー） |
| `PhotoGrid` | 横3列 |
| `PhotoTile` | 1枚。削除済みは黒画像 |
| `PhotoUpload` | 1日1人1枚の登録 |
| `PhotoReplace` | 差し替え |
| `PhotoDetail` | 拡大表示（モーダルまたは専用パネル） |
| `LikeButton` | いいね（上限999の表示は後で可） |
| `PhotoCommentList` | 詳細余白のコメント |
| `PhotoCommentForm` | 写真へのコメント入力 |

### 2.7 しおり管理 `/itineraries/[id]/admin`

作成者のみ。UI 上は表示し、権限チェックは後で API 側でも行う。

| コンポーネント | 役割 |
|----------------|------|
| `MemberList` | 参加メンバー |
| `MemberRow` | 名前・役割・BAN |
| `BanButton` | 強制退出（確認モーダル） |
| `ItinerarySettingsForm` | タイトル・パスワード・補足・期間の変更 |
| `DeleteItineraryForm` | パスワード確認つき削除 |

### 2.8 招待受領 `/invitations/[code]`

| コンポーネント | 役割 |
|----------------|------|
| `InvitationCard` | しおりタイトル、招待文言（空なら定型文） |
| `JoinItineraryForm` | パスワード＋加入ボタン |

### 2.9 設定 `/settings`

| コンポーネント | 役割 |
|----------------|------|
| `ChangeUsernameForm` | ユーザー名変更 |
| `ChangePasswordForm` | パスワード変更 |
| `LogoutButton` | ログアウト（確認モーダル可） |

## 3. モックデータの置き場（UI 検証用）

API の代わりに、コンポーネントの props に渡す固定データを置く。

| モック | 中身 |
|--------|------|
| ログイン中ユーザー | id, username, email |
| しおり一覧 | タイトル、補足、期間、作成順 |
| しおり詳細 | 編集権限、コメント解放、お約束、日次ページ |
| ロードマップ | 時刻つき予定と金額 |
| メンバー | owner / member |
| 写真 | 日付、投稿者、いいね数、削除フラグ |
| コメント | 対象要素ごとに数件 |
| 招待 | タイトル、文言、code |

コンポーネントは **API クライアントを直接呼ばない**。ページ（または後の hooks）から props で渡す。バックエンド接続時の差し替えを小さくするため。

## 4. ディレクトリ案（Next.js）

実装開始時の置き場所。まだリポジトリは切っていない。

```
app/
  login/page.tsx
  signup/page.tsx
  itineraries/page.tsx
  itineraries/new/page.tsx
  itineraries/[id]/page.tsx
  itineraries/[id]/photos/page.tsx
  itineraries/[id]/admin/page.tsx
  invitations/[code]/page.tsx
  settings/page.tsx
components/
  ui/          # Button, TextField, Modal など
  auth/        # LoginForm, SignupForm
  itinerary/   # Card, DayPage, Roadmap, Comment
  photo/       # Grid, Detail, Like
  admin/       # MemberList, Settings
  settings/    # ユーザー名・パスワード・ログアウト
mocks/         # 固定データ
```
